# 폴더 색인

## 색인의 역할

`INDEX.md`는 폴더 직속 항목의 나열과 짧은 설명으로 폴더를 빠르게 파악하는 데 쓴다. `AGENTS.md`는 폴더의 정체성과 규범을 맡고 항목을 나열하지 않으며, 할 말이 없으면 짧게 둔다. 색인은 생성 도구로만 만들고 손으로 고치지 않으며 front matter를 두지 않는다. 설명을 바꾸려면 아래 원본을 고치고 다시 생성한다.

## 색인을 두는 폴더

규범 폴더 밖에서 `AGENTS.md`가 있는 폴더마다 색인을 둔다. 디스크립터 의무의 예외가 그대로 색인의 예외다 (ref: [folder-structure.md](folder-structure.md) "폴더 구조와 디스크립터").

- 순차 분류 최상위: 폴더가 자기 `INDEX.yaml`의 예약 항목 `"."`에 `structure` 키로 구성 설명을 적어 스스로 선언한다. 그 색인은 항목 없이 구성 설명만 보이고, 그 아래 폴더에는 `AGENTS.md`가 남아 있어도 색인을 두지 않는다. `"."` 항목에 `structure`가 없거나 비었거나 다른 키가 있으면 형식 오류다. 반쯤 된 선언이 수천 항목의 나열로 조용히 바뀌지 않게 하려는 것이다.
- 중첩 저장소: 루트가 아닌 폴더의 `.git` 형태로 가른다. `.git`이 파일인 폴더(서브모듈, 연결된 worktree)는 부모 색인의 항목 하나다. `.git`이 폴더인 내장 클론은 저장소 내용이 아니라 항목에서도 git 무시 확인에서도 빠진다. 어느 쪽이든 그 안은 독립 저장소라 부모의 생성기는 색인을 쓰지 않고 부모의 감사도 대조하지 않는다.
- 색인을 두지 않는 폴더에 `INDEX*.md`나 `INDEX.yaml`이 있으면 위반이다. 순차 분류 선언이나 `AGENTS.md` 삭제로 색인 폴더에서 빠진 폴더에 남은 생성 쪽은 생성기가 지운다. `reference/` 자료 폴더 안의 같은 이름 파일은 원본 자료의 일부로 보고 건드리지 않는다.

## 항목과 설명

항목은 폴더 직속 항목에서 점으로 시작하는 것, 운영 파일(`AGENTS.md`, `CLAUDE.md`, `AGENTS/`, 색인 쪽 파일, `INDEX.yaml`), 감사 제외 폴더, 심볼릭 링크, OS(operating system)와 편집기 부산물을 뺀 전부다. 동명 문서와 폴더(`X.md`와 `X/`)는 한 줄로 합치고 `X.md`의 설명을 쓴다.

- md 문서의 설명은 front matter의 `description` 한 줄이다. 없으면 이름만 보이고 경고하지 않는다. 새 문서에 다는 것은 작성 규칙이다 (see: [communication.md](communication.md) "문서 작성 스타일").
- md가 아닌 항목과 폴더의 설명은 그 폴더의 `INDEX.yaml`에 둔다. `reference/`는 원본을 고치지 않으므로 md 자료의 설명도 `INDEX.yaml`에 둔다.

설명은 한 줄, 200자 이내다. 표준 라이브러리에 YAML 파서가 없어 유효한 YAML의 부분집합만 받는다. 따옴표 없는 값은 `"'[]{},>|*&!%@#`나 백틱으로 시작하지 않고, `: `와 ` #`를 담지 않으며, `- `나 `? `로 시작하거나 `:`로 끝나지 않는다. YAML이 수, 불리언, null, 날짜로 읽는 값(`2026-10-27`, `true`, `null` 등)도 따옴표 없이 쓰면 형식 오류다. 그 밖의 값은 `\"`, `\\`만 이스케이프하는 큰따옴표 값으로 쓴다. 여러 줄 값(`>`, `|`)은 받지 않는다. `INDEX.yaml`은 줄 전체 주석, 빈 줄, 큰따옴표로 감싼 항목 이름 줄(폴더는 끝에 `/`), 두 칸 들여 쓴 `키: 값` 줄로만 쓴다.

```yaml
# reference/INDEX.yaml
"시장 조사 원문.pdf":
  description: 시장 규모 추정의 원자료
  status: 처리 대기
"인터뷰/":
  description: "고객 인터뷰 녹취 #1 묶음"
  status: 처리됨
```

## 자료 처리 상태

`reference/` 직속 항목의 처리 진척 원본은 `reference/INDEX.yaml`의 `status`다. 항목 필드는 `description`과 `status` 둘이고, 어휘는 [reference 묶음 요지](../../reference/AGENTS/epistemic-rules.md) "처리 상태 표기"를 따른다. 색인은 상태를 백틱으로 감싸 설명 앞에 보인다. `INDEX.yaml`에 없는 항목은 `미등록`으로 보이고 감사가 경고한다. 생성기는 `INDEX.yaml`을 쓰지 않는다. 등록은 자료를 처리하는 사람과 에이전트의 일이고, 자동 등록하면 새로 들어온 자료라는 신호가 사라진다.

## 생성과 확인

- 파일을 쓰는 진입점은 생성기 하나다. 감사는 생성기와 같은 렌더 함수의 결과를 디스크와 비교한다. 실행 명령과 종료 코드는 [tools.md](tools.md) "색인 생성 스크립트".
- 생성 쪽은 첫 줄의 생성 머리말로 가린다. 색인 폴더에 머리말 없는 `INDEX*.md`(손으로 쓴 파일)가 있으면 생성기는 아무것도 쓰지 않고 그 경로를 알리며 실패한다. 내용을 다른 이름으로 옮긴 뒤 다시 돌린다.
- 쪽 나누기: 한 쪽이 공백 제외 3,000자를 넘지 않게 항목을 앞에서부터 채우고 `INDEX.md`, `INDEX2.md` 순으로 잇는다.
- 감사 강도: 색인을 둘 폴더에 `INDEX.md`가 없으면 경고, 생성 결과와 다르거나 남는 쪽 파일이 있으면 위반, `INDEX.yaml` 형식 오류는 위반, 그 밖의 설명 문제는 경고다.
- 커밋 전 훅 `tools/hooks/pre-commit`은 `git rev-parse --show-toplevel`로 얻은 저장소 루트에 생성기를 돌려 바뀐 색인 파일을 스테이지에 더한다. 생성기는 훅 파일 자신의 위치로 찾는다. Python 3.9 이상을 찾지 못하거나 생성이 실패하면 커밋을 막는다.
- 훅 연결 값(`core.hooksPath`): 상류를 머지로 받은 저장소는 `AGENTS/epistemic-rules/tools/hooks`다. 이 묶음을 머지하지 않고 서브모듈로 품은 저장소는 서브모듈 경로를 앞에 붙인 hooks 폴더를 주고 도구도 그 자리에서 실행한다. 이 생성기를 부모 루트에 돌려도 서브모듈 안은 건드리지 않는다. 자기 훅 폴더가 있는 저장소는 그 `pre-commit`에서 이 훅을 부른다.
- 훅이 막지 못하는 경우: 연결하지 않은 클론은 색인을 다시 만들지 않고, 부분 스테이징과 경로를 지정한 커밋(`git commit -- <경로>`)은 작업 트리 기준 색인을 커밋할 수 있다. 훅 경로가 없으면(초기화하지 않은 서브모듈 등) git이 훅을 조용히 건너뛴다. 이런 낡은 색인은 CI(continuous integration) 감사가 위반으로 잡는다.
- 색인 파일의 머지 충돌은 손으로 풀지 않고 생성기를 다시 돌려 푼다. `reference/AGENTS.md`의 충돌은 자손 쪽 자료 표를 남긴 채 풀고 `migrate_layout.py`로 표를 `reference/INDEX.yaml`로 옮긴다. 충돌 없이 끝난 머지는 커밋 전 훅을 거치지 않으므로 머지 뒤 `build_index.py`를 돌려 결과를 커밋한다.
- 색인을 두는 폴더 바로 아래에는 git 무시 파일을 두지 않고 `.tmp/`를 쓴다(항목이 아닌 내장 클론은 예외). 생성기는 색인 항목에 무시 파일이 있으면 실패한다. 빼고 만들면 git 없는 감사가 늘 낡은 색인으로 보고, 넣고 만들면 CI 체크아웃에 없는 파일을 가리키기 때문이다.
