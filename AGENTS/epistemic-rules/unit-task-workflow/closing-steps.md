# 종료 흐름의 단계

단위 작업 종료 흐름의 단계별 세부다. 어느 노드의 종료에서 밟는가와 단계의 순서는 [unit-task-workflow.md](../unit-task-workflow.md) "종료 흐름".

1. 마무리 커밋: 미캡처 보강, 학습 사항 반영, TASK_TREE 완료 마크와 브랜치 속성 제거를 담는다. 이 시점의 워크로그는 main 머지된 이후의 상태를 미리 기록한다. 그러면 머지 직후 그대로 정합이 맞아 별도 정정 커밋이 생기지 않는다. 확인이 머지 뒤에만 가능한 수정(예: 세션 시작 때 적재되는 지침, main에서만 도는 검사)의 노드는 `[/]`와 상태 상세의 "확인 대기"를 그대로 두고 브랜치 속성만 지운 채 머지한다. 머지 뒤 그 수정이 작동할 환경에서 확인하면 다음 단위 작업에서 완료로 표시한다 (ref: [working-principles.md](../working-principles.md) "4. 목표 주도 실행").
2. TASK_TREE 정리: 완료 마크(`[x]`/`[-]`)가 커밋에 남은 뒤에만 노드를 삭제한다(마크 커밋과 삭제 커밋 분리). 무엇을 언제 삭제하는가는 [task-tree.md](../../../worklog/AGENTS/epistemic-rules/task-tree.md)의 삭제 규칙을 따른다.
3. 사용자 검토 통과: 변경 요약(브랜치명, 변경 파일 수, 핵심 변경, 짚을 점)을 보고하고 결정 신호를 받는다. AI 자율 판단으로 머지하지 않는다.
   - 결정 갈래: OK 머지, 추가 정정(명시받아 커밋한 뒤 본 단계 반복), 롤백(브랜치 폐기).
   - 결정 신호는 명시적이어야 한다. 침묵이나 다음 작업 시작을 OK로 추론하지 않는다. 채팅 내 명시 승인("머지해")과 PR Approve가 등가다.
   - 단발 작업, 오탈자처럼 절차를 축약해 처리하는 작은 변경은 본 단계도 면제한다 (ref: [procedure-shrinking.md](procedure-shrinking.md)).
4. main 머지 - 타입 분기: PR 타입과 브랜치 관리자 타입(직접 머지) 중 하나로 진행한다. 타입 결정 규칙, 두 타입의 절차, 환경 안전망, 잔존 점검은 [merge-types.md](merge-types.md)를 따른다.
5. 서브모듈 커밋 포인터 재귀 정합화 (해당 시): 본 레포(레포지토리)가 다른 레포의 서브모듈이면 [submodule-pointer-sync.md](../submodule-pointer-sync.md)를 조립한다.
