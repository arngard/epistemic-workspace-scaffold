# main 머지 검사

자손 레포(레포지토리)가 상류 훅을 고치지 않고, main으로 들어오는 머지 커밋에서 자기 검사(단위 시험 등)를 돌리는 자리와 계약. 훅의 전체 동작은 [commit-hook.md](folder-index/commit-hook.md)에 있다.

## 자리

- 검사는 레포 루트의 `AGENTS/main-merge-checks/` 바로 아래 `*.py` 파일이다. 훅은 형식 감사가 통과한 뒤 검사 파일을 `LC_ALL=C` 이름 순으로 하나씩 실행한다.
- 이름이 `_`나 `.`으로 시작하는 파일은 도우미로 보고 실행하지 않는다. `.py`가 아닌 파일과 하위 폴더도 실행하지 않는다. 폴더가 없거나 실행할 파일이 없으면 조용히 통과한다.
- 상류는 이 폴더를 출고하지 않으므로 상류 머지가 건드리지 않는다.
- 자손 검사의 설명 문서를 두려면 `AGENTS/main-merge-checks.md`로 둔다.

## 실행 계약

- 시점: 현재 브랜치 이름이 `main`인 머지 커밋에서만 돈다. 충돌 없이 끝난 머지는 머지 커밋 전 훅이, 충돌을 풀고 `git commit`으로 마치는 머지는 커밋 전 훅이 실행한다. 일반 커밋, main이 아닌 브랜치나 HEAD가 분리된 상태의 머지에서는 돌지 않는다.
- 실행: 훅이 고른 Python으로 `python -B <검사 파일> <루트>`를 실행한다. 작업 폴더는 루트이고 표준 입력은 비어 있다.
- 환경: 훅의 환경을 물려받되, 이름이 `GIT_`로 시작하는 환경 변수(git이 훅에 넘기는 `GIT_INDEX_FILE`, `GIT_DIR`, `GIT_EDITOR` 등과 사용자가 직접 설정한 것)는 모두 지운다. 검사가 임시 레포에서 git을 돌릴 때 이 레포의 색인을 건드리지 않게 하려는 것이다. 검사 안에서 git을 이 레포에 돌리면 작업 폴더로 레포를 찾는다.
- 결과: 종료 코드 0이면 통과다. 출력 형식은 정하지 않는다. 통과한 검사는 출력을 보이지 않고 훅이 검사마다 통과 한 줄을 낸다.

## 실패

검사 하나라도 0이 아닌 값으로 끝나면 훅은 그 검사의 표준 출력과 표준 오류를 보이고 머지 커밋을 막는다. 남은 검사는 돌리지 않는다. 형식 감사가 막으면 검사는 돌지 않는다.

막힌 머지는 `git merge --abort`로 거두고, 작업 브랜치에서 원인을 고친 뒤 다시 머지한다. main 위에서 고쳐 머지를 마치지 않는다.

## 주의

- 검사는 읽기만 하고 시험 같은 확인만 한다. 작업 트리와 스테이지를 바꾸면 그 변경은 머지 커밋에 들어가지 않거나 의도하지 않게 들어간다.
- 검사가 끝날 때까지 머지 커밋이 기다린다. 제한 시간은 없다.
- 머지하면 그 레포의 검사 코드가 실행되고, 머지로 새로 들어온 검사도 그 머지에서 실행된다. 신뢰하지 않는 레포에서는 훅을 연결하지 않는다.
- GitHub 같은 원격 저장소에서 하는 머지, fast-forward 머지, `--squash` 머지는 머지 커밋 전 훅을 거치지 않아 검사도 돌지 않는다. 그때 할 일은 [commit-hook.md](folder-index/commit-hook.md)의 훅이 막지 못하는 경우 항목과 [merge-types.md](unit-task-workflow/merge-types.md) "PR 타입"에 있다.
- 세션 시작 요약과 손으로 돌리는 감사에도 들어갈 검사는 이 자리가 아니라 [audit-extensions.md](audit-extensions.md)에 둔다.
