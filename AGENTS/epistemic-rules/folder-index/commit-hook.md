# 커밋 전 훅

[folder-index.md](../folder-index.md) "생성과 확인"의 하위 문서다. 커밋할 때 색인을 다시 만들고, main으로 들어오는 머지 커밋에서 형식 감사와 main 머지 검사를 돌리는 훅의 동작과 연결 방법을 정한다.

- 커밋 전 훅 `tools/hooks/pre-commit`은 `git rev-parse --show-toplevel`로 얻은 레포(레포지토리) 루트에 생성기를 돌려 바뀐 색인 파일을 스테이지에 더한다. 도구는 훅 파일 자신의 위치로 찾는다. Python 3.9 이상을 찾지 못하거나 생성이 실패하면 커밋을 막는다.
- 스테이지에 더하다 실패해 막히면 훅은 다시 만든 색인 경로를 알린다. `git commit -a`와 경로를 지정한 커밋은 막히면 git이 훅의 스테이지를 버리고, 다음 시도의 생성기는 이미 작업 트리에 반영된 경로를 바뀐 것으로 내지 않기 때문이다. 그 경로를 직접 `git add`로 올리고 경로를 지정하지 않은 `git commit`으로 다시 커밋한다. 경로를 지정한 커밋을 다시 하면 지정하지 않은 색인이 빠진다. 같은 색인 경로에 미리 스테이지해 둔 내용은 훅이 덮는다.
- 머지 커밋 전 훅 `tools/hooks/pre-merge-commit`은 커밋 전 훅을 머지 모드로 부른다. `git merge`가 충돌 없이 머지 결과를 작업 트리에 반영한 뒤 머지 커밋을 만들기 직전에 돈다. 이 훅이 스테이지에 더한 파일은 머지 커밋에 들어가지 않으므로 머지 모드는 스테이지를 바꾸지 않고, 바뀔 색인이 있으면 머지 커밋을 멈춘다. 멈춘 머지는 그대로 남고, `git commit`으로 마치면 커밋 전 훅이 색인을 다시 만든다. 충돌을 풀고 `git commit`으로 마치는 머지도 커밋 전 훅이 색인을 다시 만든다.
- main 머지: 현재 브랜치 이름이 `main`인 머지 커밋(충돌 없이 끝난 머지와 충돌을 풀고 마치는 머지)에서만, 색인 단계 뒤에 같은 루트에 형식 감사(`audit.py`)를 돌리고, 통과하면 [main-merge-checks.md](../main-merge-checks.md)의 main 머지 검사를 돌린다. 일반 커밋과 main이 아닌 브랜치나 HEAD가 분리된 상태의 머지는 감사하지 않는다. 작업 브랜치 안의 머지는 그 브랜치가 main에 들어올 때 다시 검사된다.
- 감사가 위반이나 실행 오류로 끝나거나 main 머지 검사가 0이 아닌 값으로 끝나면 머지 커밋을 막고 그 출력을 보인다. 막힌 머지는 `git merge --abort`로 거두고 작업 브랜치에서 고친 뒤 다시 머지한다. 감사가 통과하면 요약 줄만 내고, 경고가 있으면 상세를 보는 명령을 덧붙인다.
- 감사는 레포의 감사 확장([audit-extensions.md](../audit-extensions.md))도 실행하므로 main 머지는 감사 확장과 main 머지 검사의 실행 시간만큼 늦어진다. 머지로 새로 들어온 훅과 확장, 검사도 그 머지에서 실행된다. 훅과 생성기와 마찬가지로 레포의 코드를 자동 실행하는 것이라, 신뢰하지 않는 레포에서는 훅을 연결하지 않는다.
- 훅 연결 값(`core.hooksPath`): 설치 명세의 `hooks-path` 항목이 정하고 설치기가 클론마다 맞춘다 (see: [workspace-setup.md](../workspace-setup.md)). 값은 도구 폴더 기준이라, 이 묶음을 머지하지 않고 서브모듈로 포함한 레포에서는 서브모듈 경로가 앞에 붙은 hooks 폴더(`<서브모듈 경로>/AGENTS/epistemic-rules/tools/hooks`)가 된다. 도구도 그 자리에서 실행한다. 이 생성기를 부모 루트에 돌려도 서브모듈 안은 건드리지 않는다. 자기 훅 폴더가 있는 레포는 그 `pre-commit`과 `pre-merge-commit`에서 이 두 훅을 부른다.
- 감사 대상은 머지 커밋 시점의 작업 트리다. 그래서 git이 무시하지 않는 미추적 초안의 위반도 main 머지를 막는다. 초안을 고치거나 `.tmp/`로 옮긴다.
- 훅이 막지 못하는 경우: 연결하지 않은 클론과 `--no-verify`로 건너뛴 커밋은 색인을 다시 만들지 않고 감사와 main 머지 검사도 돌지 않는다. 훅 경로가 없으면(초기화하지 않은 서브모듈 등) git이 훅을 조용히 건너뛴다. 부분 스테이징과 경로를 지정한 커밋(`git commit -- <경로>`)은 커밋 내용에 낡은 색인이 있을 수 있다. fast-forward 머지, `--squash` 머지, 원격 저장소의 웹 화면에서 하는 머지(PR 머지)는 머지 커밋 전 훅을 거치지 않아 main에 들어와도 감사와 main 머지 검사가 돌지 않고, 서브모듈의 훅을 쓰는 레포에서 서브모듈 포인터만 바뀌는 머지는 서브모듈을 새 포인터에 맞추기 전의 옛 훅으로 돈다. 이런 머지 전에는 작업 브랜치에서 `audit.py`와 main 머지 검사를 손으로 돌린다. 머지 뒤에는 머지 결과를 체크아웃한 상태에서(서브모듈은 새 포인터에 맞춘 뒤) `build_index.py --dry-run`과 `audit.py`를 돌리고, 바뀔 색인이 있으면 생성기로 다시 만들어 커밋한다. 그 밖의 경우는 세션 시작 요약이 사후에 드러낸다. 요약의 "환경 갱신" 절이 훅 연결을 점검하고, 요약의 형식 감사가 그때의 작업 트리를 본다.
