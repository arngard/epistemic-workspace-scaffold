# 서브에이전트 역할 정의

이 스캐폴드를 적용한 프로젝트에서 활용되는 서브에이전트(페르소나) 역할의 도구 중립 정의. 역할 공통 규칙은 본 문서가, 역할별 정의는 역할 목록이 링크하는 하위 문서(예: [epistemic-auditor.md](agent-roles/epistemic-auditor.md))가 담는다.

## 모델 선택

서브에이전트에 작업을 위임할 때 작업 성격에 맞는 모델을 선택한다.

- 단순 검색, 파일 나열, 정형 스캔: 경량 모델로 충분.
- 높은 수준의 언어 이해, 고차 추론, 메타인지가 필요한 작업(문서 평가, 환각(hallucination) 검증, 다중 증거 종합, 사례로부터의 귀납적 일반화, 설계 리뷰 등): opus 등 고수준 모델을 사용한다.
- 의심스러우면 고수준 모델 우선. 경량 모델이 내놓은 잘못된 결과물을 사후에 검증, 재작업하는 비용이 모델 비용 차보다 크다.

## 위임 지시와 분담

위임 지시에는 대상 정보(무엇을 가리키는지, 실제 사례), 배경(왜 이 일이 생겼는지), 범위(어디까지 판단하고 고치는지), 선택지와 각각의 함의, 판단 기준을 함께 준다. 지시만 읽은 작업자가 무엇을 왜 판단하는지 알 수 있어야 한다.

- 사용자가 맡긴 판정 범위 안에서 판정이 여럿 쌓이면 판단 기준(흔히 지속 가능성, 유연성, 효용 가치)을 주고 묶음별로 위임한다. 판정마다 여러 SSOT(single source of truth) 문서를 읽어야 닫혀 위임한 쪽의 맥락으로는 감당하기 어렵고, 묶음별 독립 작업자는 병렬로 깊이 파고들 수 있다. 판정 위임은 파일을 고치지 않고 보고만 받는다. 기준으로 가를 수 없는 것과 사용자 결정 영역은 결정 사항과 참고 정보를 정리해 [working-principles.md](working-principles.md) "1. 넘겨짚지 않는다"대로 사용자에게 올린다.
- 판정에 이은 반영도 위임한다. 위임한 쪽이 직접 반영하면 전체를 조율하는 판단이 흐려진다. 반영은 파일이 겹치지 않는 묶음으로 갈라, 위임한 쪽의 작업 브랜치에서 묶음마다 갈라낸 격리된 작업 공간([branch-strategy.md](branch-strategy.md) "작업 공간")에서 병렬로 하고 그 브랜치로 모은다. [작업 트리](../../worklog/TASK_TREE.md)는 여러 에이전트가 함께 고치면 충돌하므로 위임한 쪽이 결과를 모아 한 번에 갱신한다.
- 위임 산출물이 만든 회귀(감사 경고 증가 등)의 정정도 그 위임의 범위다.

## 역할 목록

상류가 정의한 역할의 목록이다. 인스턴스 역할은 이 표에 더하지 않고 아래 "인스턴스 전용 감사자"의 자리에 둔다.

| 역할 | 목적 | 정의 |
|------|------|------|
| epistemic-auditor | 문서 정합성 감사. 보고만 하고 수정하지 않는다. 감사자 호출, 감사 판정 기준 확인 시 읽는다 | [agent-roles/epistemic-auditor.md](agent-roles/epistemic-auditor.md) |

## 인스턴스 전용 감사자

스캐폴드를 적용한 인스턴스가 자기 도메인 고유 정책(예: 출처 표기 강화, 도메인 데이터 정합, 누적 왜곡 점검)을 감사하려면, [epistemic-auditor](agent-roles/epistemic-auditor.md)를 수정하지 않고 인스턴스 전용 감사자를 별도 역할로 둔다. 특수화 방식은 [instance-specialization.md](instance-specialization.md) "특수화 방식"을 따른다. 결정론적으로 판정할 수 있는 고유 점검은 감사자 대신 [audit-extensions.md](audit-extensions.md)의 감사 확장 지점에 둔다.

- 포함 호출: 인스턴스 감사자는 epistemic-auditor를 super로 포함해 호출한다. 한 번의 호출로 스캐폴드 공통 정합성과 인스턴스 고유 점검이 함께 수행된다.
- 등재: 인스턴스 감사자의 정의는 상류 묶음 옆 낱개 문서(예: `AGENTS/<감사자 이름>.md`)에 두고, 루트 `AGENTS.md` "이 워크스페이스의 규범" 절에서 어떤 상황에 부르는지와 함께 링크한다. 도구별 구현은 도구의 자리(예: `.claude/agents/<이름>.md`)에 둔다. 상류 묶음 파일은 고치지 않으므로(부모 불수정) 본 문서의 역할 목록과 `agent-roles/`에는 더하지 않는다.
