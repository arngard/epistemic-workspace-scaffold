# 마크다운 링크 표시텍스트

문서 간 참조 링크 `[표시텍스트](대상)`에서 표시텍스트의 정당한 형태를 정한다. 폐지된 파일명이나 옛 경로가 표시텍스트로 남으면 링크가 깨지지 않은 채 독자를 오도한다 (예: `[strategy/decision-log.md](../AGENTS.md)`는 대상 `../AGENTS.md`가 실존해 링크는 성립하나, 표시텍스트 `strategy/decision-log.md`는 존재하지 않는 파일을 가리킨다). audit 스크립트는 링크 대상의 실존뿐 아니라, 아래 원칙이 정하는 파일명 형태의 표시텍스트도 검사한다 (see: [tools.md](../tools.md) "기계 감사 스크립트").

원칙은 파일명이나 경로 형태의 표시텍스트(공백 없이 `.md`로 끝나거나 `/`를 포함한 것, 경로 성분 중 하나가 날짜 프리픽스로 시작하면서 `.md`나 `/`로 끝나는 것)가 링크 대상 자체를 가리켜야 한다는 것이다. 다음 표기가 정당하다.

- 대상 파일명(basename): `[AGENTS.md](daily/AGENTS.md)`.
- 대상 파일의 루트 기준 완전 경로: `[AGENTS/epistemic-rules/folder-structure.md](../../AGENTS/epistemic-rules/folder-structure.md)`. 대상은 상대 경로로 두고 표시텍스트로 워크스페이스 내 절대 위치를 보이는 관례.
- 링크 대상 문자열 그대로: `[../knowledge/x.md](../knowledge/x.md)`.
- 대상 경로의 끝부분: `[agent-roles/epistemic-auditor.md](../../../AGENTS/epistemic-rules/agent-roles/epistemic-auditor.md)`. 링크를 둔 문서 위치에서 대상을 풀어낸 루트 기준 경로의 뒤쪽 성분이며 `.`과 `..`을 쓰지 않는다.
- 폴더를 가리키는 링크의 폴더명: `[knowledge/](../knowledge/AGENTS.md)` (대상은 그 폴더 자체나 그 폴더의 디스크립터, 색인).

부당한 것은 없는 파일이나 대상과 다른 위치를 지칭하는 표기다.

- `[daily.md](daily/AGENTS.md)`: 실물은 `daily/AGENTS.md`이며 `daily.md` 파일은 없다. `.md`를 붙이면 이미 파일명으로 읽히므로 실존하지 않는 이름을 별칭으로 쓰지 않는다.
- `[strategy/decision-log.md](../AGENTS.md)`: `strategy/decision-log.md`는 부재 파일 (폐지된 목록 문서 잔재).
- `[old/x.md](../knowledge/x.md)`, `[../knowledge/y.md](../knowledge/x.md)`: 파일명이 같거나 실존하는 파일이어도 대상과 다른 위치를 말하는 경로다.

표시텍스트를 자유 문구로 커스텀하는 것이 정당한 경우는 둘뿐이다.

- 인라인 문구에 건 링크: 서술 문장의 일부에 링크를 거는 경우 (예: 자세한 절차는 단위 작업 흐름 문서에서 다룬다는 식).
- 대상 문서의 제목(타이틀)을 표시텍스트로 쓰는 경우.

본 규칙은 audit 스크립트가 기계 검사한다 - 파일명 형태의 표시텍스트가 위 형태로 링크 대상을 가리키는지 본다. 공백이 든 자연어 문구와 타이틀은 파일명 형태에 걸리지 않으므로 검사에서 제외된다. 날짜 문서와 폴더는 이름에 공백이 들어가므로, 날짜 프리픽스로 시작해 `.md`나 `/`로 끝나는 표시텍스트는 공백이 있어도 파일명으로 해석해 검사한다 - 서술형 문구가 이 형태를 띠면 파일명으로 읽히므로 표현을 바꾼다. 공백이 든 날짜 없는 파일명은 검사 대상 밖이다. 표시텍스트는 실제 이름(공백 포함)으로 쓰고 `%20`은 링크 대상에만 쓴다. 검사는 양쪽을 디코딩해 비교하므로 표시텍스트의 `%20`도 위반으로 보지는 않는다.
