# 워크스페이스 설치 체계

워크스페이스는 git만으로 갖춰지지 않는 환경에 기댄다(클론마다 하는 git 설정, Python과 git 같은 실행 환경). 이 환경을 설치 명세로 선언하고, 설치기 [tools/setup.py](tools/setup.py)가 점검하고 적용한다. 설치기는 AI가 부르는 도구다. 사용자는 갱신 내용과 영향 범위를 보고 동의만 한다.

## 설치 명세

- 자리: 스캐폴드 공통 항목은 [tools/setup-items.json](tools/setup-items.json), 자손 항목은 레포 루트의 `AGENTS/setup/*.json`이다. 상류는 `AGENTS/setup/`을 출고하지 않으므로 상류 머지가 건드리지 않는다.
- 형식: 항목 배열의 JSON이다. 키와 유형, 자리 표시의 세부는 [tools/_setup_core.py](tools/_setup_core.py) docstring이 정본이다. 유형은 그 클론의 git 설정(`git-config`)과 명령의 실행 가능 여부(`require-command`)다.
- 판 기준: 설치기는 명세를 main 판에서 읽는다. 작업 브랜치에서 명세를 고쳐도 main에 머지하기 전에는 갱신 알림에 나오지 않는다.
- 범위: 이 체계는 클론 안의 설정과 실행 환경의 점검만 다룬다. 레포 밖 설치(머신 전역 설정 등)가 필요한 인스턴스는 그것을 따로 다룬다.

## 점검

설치기는 상태를 저장하지 않고 세션마다 점검한다. `status`, `check`, `plan`은 항목마다 실제 점검을 돌리고 아무것도 쓰지 않는다. `apply`는 적용하는 항목의 값만 그 클론의 git 설정에 쓴다. 그래서 명세 값이 바뀐 항목, 손으로 설정을 바꾼 항목, 사용자가 미룬 항목이 모두 다음 점검에 미적용으로 다시 뜬다.

## 갱신 흐름

1. 세션 시작 요약의 "환경 갱신" 절이 미적용 갱신을 알린다(see: [session-boundaries.md](session-boundaries.md) "세션 시작").
2. AI는 `setup.py plan <루트>`의 출력으로 갱신 내용(항목, 적용이 바꾸는 것, 바뀔 키의 지금 값과 새 값)을 사용자에게 보여 주고 동의를 구한다.
3. 동의를 받은 뒤에만 `setup.py apply <루트> <id ...>`로 적용한다. 적용 뒤 결과를 사용자에게 알린다.
4. 사용자가 미루면 적용하지 않는다. 그 항목은 다음 세션의 점검에 다시 뜬다.
5. 사용자가 아무 때나 설치, 갱신, 점검을 요청해도 2-4를 밟는다. 이때는 `setup.py check <루트>`로 항목별 점검 결과를 먼저 본다.
6. 사용자가 없는 세션(예약 작업, 비대화형 실행, 서브에이전트)에서는 적용하지도, 멈춰서 묻지도 않는다. 요약의 알림만 남긴다.

설치기가 모르는 유형의 항목(이 브랜치의 설치기가 명세보다 낡았을 때)은 "도구가 명세보다 낡았다"로 알리고 적용하지 않는다. main을 받은 뒤 다시 본다.

## 처음 설치

새 클론이나 새 머신에서는 사용자가 AI에게 환경 설치를 요청한다. AI는 레포 루트에서 `setup.py check`와 `setup.py plan`을 돌려 동의를 받고 `setup.py apply`로 적용한다.

- Python은 실행할 때 `python3`, `python`, `py -3` 순으로 찾는다. 세션 시작 훅, 커밋 전 훅, 설치기의 Python 항목이 같은 순서를 쓰며, 찾은 명령을 적어 두지 않는다. 셋 다 3.9 이상의 Python을 실행하지 못하면 그 머신의 PATH에 Python 3.9 이상을 올린다. 설치 방식은 상관없다.
- AI를 쓸 수 없으면 사람이 같은 명령을 레포 루트에서 직접 돌린다: `python3 -B AGENTS/epistemic-rules/tools/setup.py check .`, `plan .`, `apply . <id ...>`(윈도우는 `python` 또는 `py -3`).

## 주의

설치 명세는 레포가 선언하므로, 남의 레포의 항목도 이 클론의 설정을 바꿀 수 있다. 바꾸는 적용의 동의는 `plan`이 보여 주는 실제 대상(지금 값과 바뀔 값, 명령)을 보고 한다. 다만 세션 시작 요약은 동의 전에 모든 항목의 점검을 돌리며, 실행 가능 여부 항목의 점검은 명세에 적힌 명령을 실행한다. 그래서 동의는 이 점검을 막지 못한다. 신뢰하지 않는 레포에서는 세션을 열거나 요약과 설치기를 실행하지 않는다.
