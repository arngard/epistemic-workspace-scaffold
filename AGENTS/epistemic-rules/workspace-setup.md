# 워크스페이스 설치 체계

워크스페이스는 git만으로 갖춰지지 않는 환경에 기댄다(클론마다 하는 git 설정, Python과 git 같은 실행 환경). 이 환경을 설치 명세로 선언하고, 설치기 [tools/setup.py](tools/setup.py)가 점검하고 적용한다. 설치기는 AI가 부르는 도구다. 사용자는 갱신 내용과 영향 범위를 보고 동의만 한다.

## 설치 명세

- 자리: 스캐폴드 공통 항목은 [tools/setup-items.json](tools/setup-items.json), 자손 항목은 레포 루트의 `AGENTS/setup/*.json`이다. 상류는 `AGENTS/setup/`을 출고하지 않으므로 상류 머지가 건드리지 않는다.
- 형식: 항목 배열의 JSON이다. 키와 유형, 자리 표시의 세부는 [tools/_setup_core.py](tools/_setup_core.py) docstring이 정본이다.
- 판 기준: 설치기는 명세를 main 판에서 읽는다. 작업 브랜치에서 명세를 고쳐도 main에 머지하기 전에는 갱신 알림에 나오지 않는다.

## 범위

항목의 범위(`scope`)는 적용 상태를 어디에 두는지를 정한다.

- `clone`: 그 클론의 git 설정에 둔다. 같은 클론의 워크트리들이 함께 쓴다.
- `machine`: 사용자 홈의 `.epistemic/` 상태 파일에 둔다.

동의와 중단 요구는 범위가 아니라 적용이 무엇을 바꾸는지로 정한다. 실행 가능 여부 항목처럼 아무것도 바꾸지 않는 항목은 상태만 머신 범위에 둔다.

## 갱신 흐름

1. 세션 시작 요약의 "환경 갱신" 절이 미적용 갱신을 알린다(see: [session-boundaries.md](session-boundaries.md) "세션 시작"). 점검이 이미 통과해 바꿀 것이 없는 항목은 동의 없이 기록하고 "기록만 한 항목" 한 줄로 알린다.
2. AI는 `setup.py plan <루트>`의 출력으로 갱신 내용(항목, 범위, 실제로 바뀔 키나 경로)을 사용자에게 보여 주고 동의를 구한다. 출력에 "다른 작업 중단 필요" 줄이 있으면, 이 머신의 다른 레포와 세션의 작업에 영향이 갈 수 있음을 알리고 진행 중인 다른 작업을 일시 중단해 달라고 요구한다.
3. 동의를 받은 뒤에만 `setup.py apply <루트> <id ...>`로 적용한다. 머신을 바꾸는 항목은 사용자가 다른 작업 중단을 확인한 뒤 `--confirm-paused`를 붙인다. 적용 뒤 결과를 사용자에게 알린다.
4. 사용자가 미루면 기록하지 않고 다음 세션에 다시 알린다.
5. 사용자가 아무 때나 설치, 갱신, 점검을 요청해도 2-4를 밟는다. 이때는 `setup.py check <루트>`로 해시와 무관하게 실제 상태를 먼저 점검해, 손으로 바뀐 설정까지 잡는다.
6. 사용자가 없는 세션(예약 작업, 비대화형 실행, 서브에이전트)에서는 적용하지도, 멈춰서 묻지도 않는다. 요약의 알림만 남긴다.

설치기가 모르는 유형의 항목(이 브랜치의 설치기가 명세보다 낡았을 때)은 "도구가 명세보다 낡았다"로 알리고 적용하지 않는다. main을 받은 뒤 다시 본다.

## 처음 설치

새 클론이나 새 머신에서는 사용자가 AI에게 환경 설치를 요청한다. AI는 레포 루트에서 `setup.py check`와 `setup.py plan`을 돌려 동의를 받고 `setup.py apply`로 적용한다.

- Python을 찾지 못하면(PATH에 없는 Python을 쓰는 머신 등) AI가 사용자에게 그 머신의 Python 실행 명령을 물어 홈의 `.epistemic/python` 파일 첫 줄에 적는다. 세션 시작 훅과 설치기가 이 파일을 먼저 쓴다. 명령은 공백으로만 나눠 읽으므로 공백이 든 경로는 쓸 수 없고, 백슬래시 경로는 그대로 쓸 수 있다.
- 홈은 환경 변수 `EPISTEMIC_HOME`이 있으면 그 값이고, 없으면 사용자 홈 폴더(Windows는 `USERPROFILE`)다.
- AI를 쓸 수 없으면 사람이 같은 명령을 레포 루트에서 직접 돌린다: `python3 AGENTS/epistemic-rules/tools/setup.py check .`, `plan .`, `apply . <id ...>`(윈도우는 `python` 또는 `py`).

## 주의

설치 명세는 레포가 선언하므로, 남의 레포의 항목도 이 머신의 설정을 바꿀 수 있다. 동의는 `plan`이 보여 주는 실제 대상(키, 경로, 명령)을 보고 한다. 신뢰하지 않는 레포의 항목은 적용하지 않는다.
