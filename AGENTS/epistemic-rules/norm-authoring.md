# 규범 작성

규범과 절차를 더하거나 고치거나 지울 때의 기준이다. 규범은 읽는 쪽의 주의를 쓰므로, 불필요한 문장은 필요한 문장의 준수 가능성까지 낮춘다. 문서 일반의 순서는 [document-authoring.md](document-authoring.md), 상속 자산을 고칠 때의 분기는 [instance-specialization.md](instance-specialization.md) "변경의 분기"를 따른다.

## 문장을 남길지 가리기

문장마다 순서대로 묻는다.

1. 없어지면 운영에 문제가 생기는가. 그렇다면 보존하고 아래 질문은 표현을 줄이는 데만 쓴다. 아니라면 아래 질문으로 넘어가고, 어느 질문에도 걸리지 않는 문장은 남긴다.
2. 적혀 있지 않아도 작업자가 그렇게 하는가. 그렇다면 적지 않는다.
3. 기계 감사나 도구가 강제하는가. 그렇다면 강제되는 내용을 다시 적지 않고, 강제가 못 미치는 판단만 적는다.
4. 다른 문서에 같은 내용이 있는가. 그렇다면 [document-units.md](document-units.md) "중복 금지"대로 링크한다.
5. 앞 문장과 정보량이나 해상도가 크게 다른가. 아니라면 합쳐서 한 문장으로 쓴다.

말에 정의를 붙일지는 [writing-style.md](writing-style.md) "통용되는 개념의 정의"를 따른다.

## 규범을 정할 때

- 지속 가능성: 작업이 쌓이고 작업자와 도구가 바뀌어도 계속 지키고 유지할 수 있는 규범으로 정한다. 지키거나 고치는 비용이 갈수록 커지는 규범은 형태를 바꾼다.
- 곡해 가능성: 규범이 나온 논의를 모르는 독자가 문장만 읽고 뜻을 넓히거나 다르게 읽을 수 있는지 본다. 그럴 수 있으면 적용 범위와 한정 조건을 문장에 넣어 고친다.
- 정합성: 같은 영역과 맞닿은 규범을 읽고 대조해, 규범끼리 충돌하지 않게 하고 서로를 근거로 삼거나 서로에게 내용을 미뤄 순환하지 않게 한다. 어긋나면 어느 쪽을 고칠지 정해 같은 작업에서 고친다.

## 자리 정하기

- 상류와 자손: [instance-specialization.md](instance-specialization.md) "특수화 방식"의 상류와 자손의 자리 항목.
- 폴더: 규범은 다루는 영역 가까이에 둔다. 여러 영역을 가로지르는 규범만 루트 묶음에 둔다. 폴더별 규범 폴더의 형식은 [folder-structure.md](folder-structure.md) "폴더 구조와 디스크립터".
- 늘 적재되는 층: 요지, 소통 규약, 작업 흐름에는 모든 작업에 걸리는 규범만 두고 나머지는 트리거와 링크로 둔다.
- 게이트: 요지 "비협상 게이트"의 기준에 드는 것만 올린다.
- 근거: 규범 본문에는 이유를 모르면 되돌릴 위험이 있는 근거 요지만 둔다 (ref: [document-temporality.md](document-temporality.md) "시간성 혼합 금지").

## 입구 유지

규칙은 영역 문서에 한 번만 두고, 작업 입구는 순서와 링크만 담는다. 입구에 규칙을 옮겨 적으면 원문이 바뀔 때 어긋난다.

- 새 규범 문서는 읽을 때를 묶음 요지의 트리거나 부모 문서 본문에 적는다. 루트 요지 "이럴 때 읽는다"에 올리면 작업, 상황, 확인 가운데 한 갈래에 둔다. 자손 규범은 그 폴더 `AGENTS.md`에 등재한다.
- 트리거는 작업이나 상황의 이름으로 시작하고, 한 경우를 다른 말로 되풀이하지 않는다.
- 작업이 여러 문서를 거치고 절차 문서 하나로 묶이지 않으면 [document-authoring.md](document-authoring.md) 같은 입구 문서를 둔다.
- 절차 문서나 입구 문서를 신설하면 [tool-environment.md](tool-environment.md) "Claude Code 래퍼(절차 스킬, 서브에이전트)"대로 래퍼가 필요한지 정한다.
- 여러 단계로 나뉜 절차는 [unit-task/stage-authority.md](unit-task/stage-authority.md)로 판정 권한을 정한다.

## 고치거나 지울 때

- 옮기거나 지운 규칙의 파일 이름, 절 이름, 핵심 어구로 저장소 전체를 찾는다. 코드 주석, 도구, 스킬, 시험도 규범을 인용한다.
- 문장을 줄인 뒤 원본과 대조해 적용 범위와 한정 조건이 남았는지 본다.
- 규범의 이동과 리네임은 [folder-structure.md](folder-structure.md) "폴더, 파일 이동 시 연쇄 갱신"을 따른다.
