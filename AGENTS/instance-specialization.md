# 상속 자산의 변경과 특수화

이 스캐폴드를 상속한 인스턴스에서 계승된 자산(규범 문서, 절차, 역할 정의, 템플릿)을 다루는 규약. 인스턴스가 자기 도메인 문서를 쓰는 일에는 적용되지 않고, 상류에서 내려온 자산을 고치거나 자기 도메인에 맞춰 특수화할 때 적용된다.

두 가지를 막는다. 도메인과 무관한 개선이 한 인스턴스에 갇히면 같은 깨달음이 다른 인스턴스들에서 다시 도출되고, 그 사이 같은 규칙의 판본이 갈라져 의도된 특수화인지 반영 누락인지 구분되지 않게 된다. 그리고 계승 본문을 제자리에서 고치면 상류 머지마다 충돌이 재발해 부모의 개선을 받기 어려워진다.

## 변경의 분기

상속 자산에 대한 규칙 변경을 도출하면 제자리 수정 전에 두 갈래를 명시적으로 분기해 사용자에게 짚는다.

- 상류 반영: 변경이 도메인과 무관한 일반 개선이면 이쪽을 기본 가정으로 둔다. 상류 자산을 SSOT(single source of truth)로 유지하고 인스턴스는 머지로 받는다.
- 인스턴스 특수화: 변경이 그 인스턴스 도메인 고유 사정에 한정되거나, 상류에 두면 다른 인스턴스에 부적절한 부담이 될 때만 이쪽으로 간다.

어느 쪽인지 판단이 서지 않으면 상류 반영이 기본이다. 이 분기를 묻지 않고 인스턴스만 고치고 끝내지 않는다.

## 특수화 방식

인스턴스 특수화로 정했을 때 다음을 지킨다.

- 부모 불수정: 계승된 자산의 본문을 고치지 않는다. 고치면 상류 머지마다 충돌하고 부모 개선의 유입이 막힌다.
- 표준을 포함해 완주: 인스턴스 자산은 상류 표준을 포함해 그 절차를 먼저 완주한 뒤 도메인 단계를 더한다. 표준의 단계를 인스턴스 문서로 옮겨 적지 않는다 - 복제하면 상류가 갱신될 때 어긋난 합집합이 남고, 인스턴스 문서만 읽은 작업자가 표준 단계를 건너뛴다.
- 역할 분담: 상류 자산은 공통 사항만 담고, 도메인 고유 항목은 인스턴스 자산의 정의에만 둔다.
- 라우팅으로 등재: 진입점과 색인에 인스턴스 자산을 등재할 때 계승된 문장 자체는 수정하지 않고, 하위 항목으로 어떤 상황이면 인스턴스 자산을 쓰는지의 라우팅 조건을 더한다.

역할 정의에 적용한 구체 사례는 [agent-roles.md](agent-roles.md) "인스턴스 전용 감사자" 참조.

## 상류 흡수의 의미 정합

상류 머지는 파일 반영으로 끝나지 않는다. 흡수한 변경이 규범(규칙, 절차, 판정 기준)의 변경이면, 같은 단위 작업 안에서 인스턴스의 기존 문서와 구조를 새 규범과 대조하는 의미 검토를 동반한다. 충돌 없는 머지가 정합을 보증하지 않는다 - 충돌은 같은 파일의 같은 자리가 갈렸을 때만 나고, 규범과 구조의 어긋남은 서로 다른 파일에 있다. 규범이 도착해도 기존 구조가 옛 규범대로 남아 있으면 판본이 갈라진 것과 같다.

검토의 산출은 셋 중 하나다.

- 정합: 새 규범이 걸리는 구조가 인스턴스에 없거나 이미 부합한다. 조치 없음.
- 정정 또는 미결 등재: 기존 구조가 새 규범과 어긋난다. 즉시 고치거나, 판단이 필요하면 작업 트리에 등재한다.
- 예방 등재: 아직 없는 구조(미작성 절차 등)에 새 규범이 걸릴 것이 예견되면, 그 설계 시점에 적용하도록 작업 트리에 남긴다.

콘텐츠 추가나 오탈자 수준의 상류 변경은 본 검토 대상이 아니다 - 대조할 규범이 없다.
