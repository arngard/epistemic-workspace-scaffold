# 작업 트리 운영 지침

[TASK_TREE.md](../../TASK_TREE.md)의 노드 유형, 표기, 갱신 규칙, 삭제 규칙이다.

작업의 계층 구조. 큰 작업이 어떤 하위 작업으로 구성되는지를 기록한다.
현재와 가까운 전후의 작업 상태를 표현하는 현재적 문서이며, 이력 보관소가 아니다. 완료 이력의 SSOT(single source of truth)는 git 이력이다.
"다음에 뭘 해야 하는가"는 이 트리에서 `[ ]` ready인 것 중 가장 앞에 있는 리프 노드.

노드 유형 2종:
- 작업 노드: 체크박스를 가진 불릿. 깊이 제한 없음. 모든 작업 노드는 깊이와 무관하게 동일한 "작업"이다. 노드 줄 자체가 제목이며 한 구절이나 한 문장으로만 쓴다. 배경, 상세, 해시는 노드 줄에 붙이지 말고 하위 설명 속성 노드로 내리고, 하위 작업은 하위 작업 노드로 내린다.
- 속성 노드: 체크박스 없는 불릿(`-`). 부모 작업 노드의 속성을 서술한다. 표준 키는 설명, 상태 상세, 외부 참조, 브랜치. 필요한 것만 이 순서로 둔다. 외부 참조는 Jira, Linear 등 외부 티켓 관리 도구의 티켓을 가리키며 복수일 수 있다. 브랜치 속성은 작업이 `[/]`로 진입할 때 기재하고 완료 머지 후 제거한다.

체크박스 표기:
- `[ ]` ready: 대기 중. 시작되지 않음.
- `[/]` incomplete: 진행 중이거나 중단됨.
- `[x]` done: 완료됨.
- `[-]` canceled: 취소됨 또는 큰 난관으로 닫힘.
- 들여쓰기로 부모-자식 관계 표현.
- 같은 깊이의 형제 노드는 위상 정렬(topological order): 의존성상 먼저 해야 하는 것이 앞. 의존 관계가 없는 형제끼리는 앞에 놓인 것을 먼저 한다. 루트 노드끼리도 같다.

갱신 규칙:
- 작업 종료 시: 완료 항목을 `[x]`로 전환하고, 새로 드러난 항목을 추가한다. 위상 정렬을 유지한다.
- 속성 노드는 최소한으로 유지한다. 해당 작업에 문서가 있으면 설명 속성에 `sub:` 링크만 남기고 설명은 문서에 둔다.
- 완료 시 브랜치 속성만 제거하고, 나머지 속성은 서브트리가 제거될 때까지 유지한다.
- 래퍼 노드 금지. 하위 작업을 묶기만 하는 의미 없는 상위 노드는 만들지 않는다. 상위 노드는 그 자체로 완료 가능한 작업이거나 의미 있는 서브트리의 루트여야 한다. 단순 그룹핑은 형제 노드 간 위상 정렬과 인접 배치로 표현한다.

삭제 규칙:
- `[x]`/`[-]` 마크가 커밋에 이력으로 남은 뒤에만 삭제한다(마크 커밋과 삭제 커밋을 분리한다).
- 완결된 루트 노드(모든 자식이 `[x]` 또는 `[-]`)는 서브트리째 트리에서 제거한다. 다음 작업 시작 전에 사용자에게 커밋을 제안하고, 사용자가 보류하면 다음 라운드까지 보존한다.
- 완료된 중위 노드는 그 하위(자식 노드)를 삭제해 정리할 수 있다. 노드 제목만으로 무슨 작업이었는지 유추하기 어려운 경우에 한해 간략한 설명(속성 노드)만 남긴다. 완료 노드 자체는 제목으로 잔존해 진행 흐름을 보이며, 조상 루트가 삭제되면 함께 제거된다.

기대 형태:

```
- [/] 부모 작업 노드
  - [/] 자식 작업 노드
    - 노드에 대한 설명
    - 노드의 작업 상태
    - 노드에 관한 외부 티켓 관리 툴 참조 (복수 가능)
    - 노드의 작업이 진행 중인 브랜치
  - [ ] 다른 자식 작업 노드
    - 노드에 대한 설명
```
